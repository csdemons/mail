# Если что-то не работает

[← К оглавлению](README.md)

## Диагностика

- **Почта IMAP**: Настройки → «Диагностика» — ответы сервера по текущей папке (CAPABILITY,
  LIST, STATUS, FETCH), SMTP, CalDAV/CardDAV, веб-API SOGo. Пароля в отчёте нет.
- **Exchange**: на вкладке «Exchange» экрана входа после ошибки — «Диагностика подключения»:
  адрес EWS, DNS, сертификат, способы входа сервера, шаги NTLM, версия Exchange и ответ EWS.
  Проверка делает до трёх попыток входа — учитывайте порог блокировки учётной записи в AD.

Отчёт можно скопировать и отправить администратору или разработчику.

## Exchange

| Что видно | Причина и что делать |
|---|---|
| «Autodiscover предлагает сервер … — он не в домене почты» | Сервер Exchange в другом домене, чем почта. Укажите сервер вручную или попросите администратора добавить домен в `exchangeHosts` политики. |
| «Сервер Exchange не найден автоматически» | Нет `autodiscover.<домен>`. Укажите сервер: `mail.организация.ru`. |
| «Неверный логин или пароль» | Проверьте логин в виде `ДОМЕН\имя` (или `имя@домен`). Если пароль точно верный — запустите диагностику: в 0.30.2 исправлен случай, когда IIS отвечал «411 Length Required». |
| «Сервер Exchange ответил HTTP … на начало входа NTLM» | Перед EWS стоит прокси или страница входа; нужен прямой адрес EWS или Basic по HTTPS. |
| «Сервер Exchange закрывает соединение посреди входа NTLM» | Обратный прокси не держит соединение для NTLM. Нужен прямой доступ к серверу или разрешённый Basic по HTTPS. |
| «сертификат сервера … не принят системой» | Сертификат выдан внутренним центром сертификации — установите его корневой сертификат в доверенные на компьютере. |
| «Адрес Exchange перенаправляет запросы» | Указан адрес веб-почты (OWA). Нужен адрес EWS: `https://сервер/EWS/Exchange.asmx`. |

## Почта IMAP

- **Папки пустые или «нет UIDVALIDITY»** — программа переподключается сама; если повторяется,
  пришлите отчёт диагностики.
- **Сертификат не принят** — как для Exchange: установите корневой сертификат организации.
- **Пароль спрашивается при каждом запуске (Linux)** — нет системного хранилища паролей
  (GNOME Keyring/KWallet) или оно заблокировано.

## Политика администратора

«Политика администратора не принята … включены строгие ограничения» — файл `policy.json`
повреждён или имеет неверные права (нужно `root:root 644`). См.
[руководство администратора](admin-guide.md#политика).

## Работа без сети

- Плашка «Нет связи» — программа проверяет связь каждые 15 секунд; «Проверить связь» — сразу.
- «Не всё из сделанного без сети удалось выполнить» — письмо, с которым было действие, за это
  время удалили, переместили или папку пересоздали. Откройте список и решите сами.

## macOS

«Не удаётся проверить разработчика» при первом запуске — «Системные настройки →
Конфиденциальность и безопасность → Всё равно открыть» или
`xattr -dr com.apple.quarantine "/Applications/RRCKI Mail.app"`.

## Сообщить об ошибке

[Issues](https://github.com/csdemons/mail/issues): версия (Настройки → О программе), система,
что делали, что увидели, отчёт диагностики. Не прикладывайте пароли и содержимое писем.
