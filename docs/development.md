## Окружение

Node.js 22+, Rust stable и системные пакеты.

- **Windows:** [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
  («Разработка классических приложений на C++»), WebView2 (в Windows 10/11 уже есть).
- **Linux (Ubuntu 22.04+, Debian 12, Astra 1.8):**
  ```bash
  sudo apt install libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev \
    libssl-dev libsecret-1-dev build-essential
  ```

```bash
npm install     # зависимости, в том числе frontend
npm run dev     # окно приложения с hot reload
npm run build   # установщики в src-tauri/target/release/bundle/
```

**Новая команда Tauri** пишется в модуле своей области в `src-tauri/src/commands/` и добавляется
одной строкой в `src-tauri/commands.list` (`имя` или `имя msg`, если она
нужна окну письма). Остальное `build.rs` делает сам (`build_commands.rs`, общий для обеих сборок):
обработчик `app_commands!()`, разрешения `allow-<команда>` и `capabilities/*.json`.
Сборка не пройдёт, если функция с `#[tauri::command]` не указана в списке или в списке есть лишнее.
Созданные файлы (`capabilities/*.json`, `permissions/autogenerated/*.toml`) коммитятся;
CI проверяет, что они совпадают со списком. Новый
модуль добавляется в `lib.rs` и в `legacy/src/main.rs` через `#[path]`.

**Размер файлов.** `.ts/.tsx` — до 800 строк, Rust — до 1500. Файлы, которые уже больше,
перечислены в `file-size-baseline.json`: им можно вырасти не больше чем на 50 строк (CI
предупреждает о любом росте). Проверка — `node frontend/scripts/check-file-size.mjs`, после
уменьшения файла — с `--update`. Вынести кусок JSX в отдельный компонент помогает
`node scripts/extract-component.mjs <файл> <Компонент> <с строки> <по строку> <Новый> <путь>`
(из `frontend/`): свойства с типами и импорты он выводит через TypeScript.

## Тесты

```bash
cd src-tauri && cargo test && cargo clippy --all-targets -- -D warnings
sudo bash tests/imap-server/setup.sh      # IMAPS localhost:10993 (test@corp.test / Secret-123)
sudo bash tests/servers/start.sh          # SMTPS :465, CalDAV/CardDAV :5232, Nextcloud :8443, SOGo :8444, EWS :8445
npx tauri build --debug --no-bundle
dbus-run-session -- tests/e2e/run.sh tests/e2e/e2e.py /tmp/shots   # ~10 минут
```

E2E (Xvfb, GNOME Keyring, tauri-driver) проходит всю программу: вход, почту, редактор,
календарь, контакты, Nextcloud, правила, поиск, работу без сети (через iptables), несколько
учётных записей, Exchange (NTLM с проверкой MIC и привязки к TLS), XSS в письмах; снимки экранов —
в каталоге из аргумента. Имитация EWS, как IIS, отвечает 411 на POST без длины тела и требует,
чтобы вход NTLM шёл по одному соединению.

Проверка ядра против реального сервера без интерфейса:
```powershell
$env:IMAP_USERNAME = 'login'; $env:IMAP_PASSWORD = Read-Host -MaskInput
cd src-tauri; cargo run --example smoke
```

## Выпуск версии

1. Поднять версию в `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json` и `legacy/tauri.conf.json`.
2. Раздел в `CHANGELOG.md` (он же — «Что нового» в программе), при необходимости — `SECURITY.md`.
3. Юнит-тесты, clippy (Linux и Windows), E2E.
4. Push в `main`: CI собирает пакеты для всех систем и после подтверждения в среде `release`
   публикует релиз `vX.Y.Z` с подписанными `latest.json` и `SHA256SUMS.txt`.

Если GitHub не выделил машину macOS, релиз выходит без пакета для неё; перезапуск задания
«Bundle (macos)» потом добавит пакет к выпущенному релизу (и `mac` в `latest.json`).
