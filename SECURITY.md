# Безопасность Atom Mail (RRCKI Mail)

Что защищено и как — для администраторов и аудита. Об уязвимостях сообщайте
разработчику (Юшков Д. О.) напрямую, не в публичных issue.

## Учётные данные
- Пароль почты и пароль приложения Nextcloud — только в системном хранилище
  (Windows Credential Manager, Secret Service / GNOME Keyring). В `settings.json` паролей нет.
- `settings.json` в Linux — каталог `0700`, файл `0600`, запись атомарная.
- Если хранилища нет (терминальный сервер без keyring) — пароль не сохраняется,
  его спрашивают при каждом запуске; программа об этом предупреждает.
- Пароль почты уходит только на: IMAP-сервер (TLS ≥ 1.2, проверка сертификата
  системным хранилищем), SMTP-сервер (TLS), сервер календаря/контактов из настроек.
  DAV-запросы и перенаправления на другой хост, порт или с https на http выполняются
  без пароля — отклоняются.
- «Выйти» удаляет пароль почты, отзывает пароль приложения Nextcloud на сервере,
  очищает кэши и закрывает окна писем. Вход другого сотрудника не наследует чужой
  Nextcloud, имя отправителя и сессию SOGo.
- Диагностика не содержит паролей и значений cookie (только имена).

## Письма
- HTML очищается (ammonia: без скриптов, обработчиков событий, `javascript:`-ссылок,
  форм, iframe) и показывается в `iframe sandbox` без `allow-scripts`; CSP окна
  разрешает картинки только `self` и `data:` — страница сама в сеть не ходит.
- Встроенные картинки (`cid:`) подставляются как `data:` (до 25 МБ на письмо).
- Картинки из интернета — только по кнопке. Их загружает программа: только http/https
  на портах 80/443/8080/8443, без логина в URL; имя разрешается заранее и **все** адреса
  должны быть публичными (запрещены loopback, частные сети, link-local, CGNAT,
  multicast, `169.254.169.254` и т.п., в том числе через IPv4-mapped/NAT64/6to4);
  соединение идёт на проверенный адрес (защита от DNS rebinding), без прокси;
  каждое перенаправление проверяется заново (не больше 3); до 5 МБ на картинку,
  25 МБ на письмо, 6 загрузок одновременно, только `image/*`.
- Ссылки из писем открываются в браузере, только `http`, `https`, `mailto`.
- Вложения сохраняются через системный диалог, имена очищаются от путей.
  Предпросмотр: картинки (`<img>` с `data:`), текст (как текст), PDF — pdf.js 6
  (без eval, без XFA), до 30 МБ.
- Удаление без UIDPLUS: чужие письма с `\Deleted` не удаляются нашим EXPUNGE
  (пометка временно снимается и возвращается).

## Интерфейс и IPC
- Команды бэкенда регистрируются явно (`app_commands!`). Чтение файлов с диска —
  только тех, что пользователь выбрал в системном диалоге (по выданному id).
  Произвольных путей, запуска процессов по запросу интерфейса нет; установщик
  обновления запускается только после проверки подписи и SHA-256.
- Окна писем получают параметры через JSON (`serde_json`), без подстановки строк в код.
- `style-src 'unsafe-inline'` нужен для встроенных стилей интерфейса (React) и писем;
  скрипты — только из пакета приложения (`default-src 'self'`).

## Обновления
- `latest.json` подписывается в CI ключом Ed25519 (секрет `UPDATE_SIGNING_KEY`),
  подпись — `latest.json.sig`, открытый ключ встроен в `updater.rs`
  (`UPDATE_PUBLIC_KEYS`, можно несколько — для смены ключа).
- Без верной подписи обновление не предлагается; без корректной SHA-256 файл
  не скачивается; версия не выше текущей не предлагается (нет отката).
- Только https; источник меняет только администратор (`update.json` в
  `/etc/rrcki-mail/` или `%ProgramData%\RRCKI Mail\`). Отладочные переменные
  `RRCKI_E2E_*` в релизной сборке не действуют.
- Для GPO рекомендуется отключить самообновление (`"disabled": true`) и раздавать
  проверенные пакеты из внутреннего хранилища.
- Подпись кода Windows (Authenticode) и deb/rpm не выполняется — нужен сертификат
  организации; пакеты проверяются по `SHA256SUMS.txt` + `SHA256SUMS.txt.sig`.

### Проверка релиза вручную
```sh
base64 -d SHA256SUMS.txt.sig > /tmp/sums.sig
echo "MCowBQYDK2VwAyEAUhcIkgOlNtHqJjtYlNf4Ij6HHuRbEgFNh+zptMcVBaY=" | base64 -d > /tmp/pub.der
openssl pkey -pubin -inform DER -in /tmp/pub.der -out /tmp/pub.pem
openssl pkeyutl -verify -pubin -inkey /tmp/pub.pem -rawin -in SHA256SUMS.txt -sigfile /tmp/sums.sig
sha256sum -c SHA256SUMS.txt --ignore-missing
```

## Сборка и поставка
- GitHub Actions закреплены по SHA коммита; токен по умолчанию — только чтение,
  `contents: write` — лишь у задачи релиза.
- В CI: `npm audit --omit=dev --audit-level=high`, `cargo audit` (RustSec) для обеих
  сборок, clippy `-D warnings`, юнит-тесты.
- К релизу прикладываются SBOM (CycloneDX: Rust, Rust для Astra 1.7, frontend),
  `SHA256SUMS.txt` и подписи.
- Рекомендуется: защита ветки `main` (обязательные проверки, запрет force-push),
  2FA для всех, кто может пушить, отдельная среда (environment) с подтверждением для
  задачи релиза — тогда секрет подписи доступен только ей.
