# Безопасность Atom Mail (RRCKI Mail)

Что защищено и как — для администраторов и аудита. Об уязвимостях сообщайте
разработчику (Юшков Д. О.) напрямую, не в публичных issue.

## Учётные данные
- Пароль почты и пароль приложения Nextcloud — только в системном хранилище
  (Windows Credential Manager, Secret Service / GNOME Keyring). В `settings.json` паролей нет.
- `settings.json` в Linux — каталог `0700`, файл `0600`, запись атомарная.
- Если хранилища нет (терминальный сервер без keyring) — пароль не сохраняется,
  его спрашивают при каждом запуске; программа об этом предупреждает.
- Пароль почты уходит только на: IMAP-сервер (TLS ≥ 1.2, проверка сертификата
  системным хранилищем), SMTP-сервер (TLS), сервер календаря/контактов из настроек —
  **только по https** (адрес с http не сохраняется; SOGo — тоже только https).
  DAV-запросы и перенаправления на другой хост или порт выполняются без пароля — отклоняются.
- Смена адресов серверов в настройках требует ввести пароль почты (даже чужой код в
  интерфейсе не сможет перенаправить пароль на свой сервер).
- «Выйти» удаляет пароль почты, отзывает пароль приложения Nextcloud на сервере,
  очищает кэши и закрывает окна писем. Вход другого сотрудника не наследует чужой
  Nextcloud, имя отправителя и сессию SOGo.
- Диагностика не содержит паролей и значений cookie (только имена).

## Защита кодом (TOTP)

Необязательный замок на программе (включает пользователь в настройках):

- Код по RFC 6238 (HMAC-SHA1, 6 цифр, шаг 30 с, допуск ±1 шаг); один и тот же шаг дважды не принимается.
- Секрет (160 бит из ОС-генератора) и SHA-256 восьми одноразовых резервных кодов хранятся только в системном хранилище паролей (служба `ru.rrcki.mail.totp`, запись `user@host`). Без работающего хранилища защиту не включить.
- Пока код не введён, бэкенд не подключается к IMAP/SMTP/DAV/Nextcloud: учётные данные лежат только в памяти процесса, все команды почты отвечают «не выполнен вход». При ручном входе пароль сначала проверяется на сервере, сохраняется в хранилище — только после кода.
- Блокировка (Ctrl+L, меню, бездействие) закрывает соединения и окна писем.
- Перебор: после 5 неверных кодов — пауза 30 с, удваивается с каждой ошибкой (до 32 мин).
- Отключение — только с текущим или резервным кодом. «Потерян телефон и резервные коды» на экране блокировки снимает защиту **и** забывает сохранённый пароль: снова войти можно только по паролю почты.

Ограничения: это защита от чтения переписки на оставленном без присмотра компьютере (в том числе при сохранённом пароле), а не второй фактор почтового сервера — пароль почты действует в веб-почте и других клиентах. Пользователь ОС с доступом к его хранилищу паролей (тот же сеанс) может прочитать и пароль, и секрет; от этого защищает блокировка сеанса ОС.

## Письма на компьютере (локальное хранилище)

- Индекс заголовков всех писем своих папок (отправитель, получатели, тема, дата, флаги) и исходники писем за выбранный срок (по умолчанию 7 дней, не больше 15 МБ каждое) — в `<локальные данные программы>/mailstore/<хэш учётной записи>/` (Linux: `~/.local/share/ru.rrcki.mail/`, Windows: `%LOCALAPPDATA%\ru.rrcki.mail\`), каталог 0700.
- Каждый файл зашифрован XChaCha20-Poly1305 (случайный nonce, имя файла — в связанных данных); ключ 256 бит — в системном хранилище паролей (служба `ru.rrcki.mail.store`). Без ключа (другой пользователь, копия диска или профиля, резервная копия) файлы не читаются; каталог без ключа удаляется и собирается заново.
- Общие ящики не индексируются. Синхронизация — отдельным IMAP-соединением, только чтение (EXAMINE, BODY.PEEK), раз в 10 минут; исходники старше срока удаляются.
- Блокировка (TOTP) закрывает хранилище; «Выйти и забыть пароль» удаляет каталог и ключ. Администратор может запретить хранение (`localStore: false`) — например, на терминальных серверах — тогда всё уже сохранённое удаляется при следующем входе.

## Письма
- HTML очищается (ammonia: без скриптов, обработчиков событий, `javascript:`-ссылок,
  форм, iframe) и показывается в отдельной рамке со своей политикой CSP — строже окна:
  `default-src 'none'; script-src 'none'; img-src data:; form-action 'none'; base-uri 'none'`
  (плюс CSP окна): ни скриптов, ни обращений в сеть, ни форм. Атрибут `sandbox` не
  используется сознательно: в WebKitGTK с ним не срабатывают обработчики щелчков из
  программы, и ссылки из писем нельзя было бы проверить (подозрительный домен) и открыть
  в браузере; защиту от исполнения кода дают очистка и CSP рамки — проверено автотестом.
- Встроенные картинки (`cid:`) подставляются как `data:` (до 25 МБ на письмо).
- Картинки из интернета — только по кнопке и по политике администратора
  (`remoteImages`: `direct` — напрямую, `proxy` — через системный/корпоративный прокси,
  `off` — не загружаются; `internalNetworks` — внутренние сети, куда обращаться нельзя,
  в том числе ваши публичные блоки адресов). В режиме `direct` их загружает программа: только http/https
  на портах 80/443/8080/8443, без логина в URL; имя разрешается заранее и **все** адреса
  должны быть публичными (запрещены loopback, частные сети, link-local, CGNAT,
  multicast, `169.254.169.254` и т.п., в том числе через IPv4-mapped/NAT64/6to4);
  соединение идёт на проверенный адрес (защита от DNS rebinding), без прокси;
  каждое перенаправление проверяется заново (не больше 3); до 5 МБ на картинку,
  25 МБ на письмо, 6 загрузок одновременно, только `image/*`.
- Ссылки из писем открываются в браузере, только `http`, `https`, `mailto`; реальный
  адрес виден под письмом при наведении; если текст ссылки показывает другой домен, чем
  она ведёт, — предупреждение «Ссылка ведёт не туда, куда написано».
- Вложения сохраняются через системный диалог, имена очищаются от путей.
  Предпросмотр: картинки (`<img>` с `data:`), текст (как текст), PDF — pdf.js 6
  (без eval, без XFA), до 30 МБ.
- Удаление без UIDPLUS: чужие письма с `\Deleted` не удаляются нашим EXPUNGE
  (пометка временно снимается и возвращается; между шагами другой клиент может
  на мгновение увидеть письмо без пометки). У RuPost/Dovecot UIDPLUS есть.
- Копия в «Отправленные» после таймаута не повторяется — без дублей.
- Файлы Nextcloud скачиваются и загружаются потоком (не целиком в память); размер
  вложений письма проверяется до чтения файла.
- PDF рисует pdf.js 6 в главном окне (без eval, CSP без `unsafe-eval`); отдельная
  песочница для PDF — в планах.

## Интерфейс и IPC
- Команды бэкенда объявлены в `build.rs` (AppManifest) и разрешаются по окнам:
  главное окно — все, окна писем (`msg-*`) — только 23 команды, нужные письму
  (`capabilities/message-window.json`), окна редактора документов (`doc-*`) — ни одной.
  В сборке для Astra 1.7 (Tauri 1) такого разделения нет — там защита держится на CSP.
- Окно редактора документов не уходит со своего Nextcloud и его домена: прочие ссылки
  открываются в браузере, новые окна не создаются.
- Команды бэкенда регистрируются явно (`app_commands!`). Чтение файлов с диска —
  только тех, что пользователь выбрал в системном диалоге (по выданному id).
  Произвольных путей, запуска процессов по запросу интерфейса нет; установщик
  обновления запускается только после проверки подписи и SHA-256.
- Окна писем получают параметры через JSON (`serde_json`), без подстановки строк в код.
- `style-src 'unsafe-inline'` нужен для встроенных стилей интерфейса (React) и писем;
  скрипты — только из пакета приложения (`default-src 'self'`).

## Обновления
- Пакет скачивается в личный каталог пользователя (`$XDG_RUNTIME_DIR/rrcki-mail` или
  `~/.cache/rrcki-mail`, 0700, новый подкаталог на каждую загрузку, файлы с O_EXCL и без
  перехода по ссылкам), SHA-256 сверяется ещё раз по файлу на диске непосредственно
  перед установкой. Общий `/tmp` не используется (иначе на терминальном сервере другой
  пользователь мог бы подменить пакет до установки через pkexec). Откат версий при
  установке через apt не разрешается.
- Windows: повышение прав — ShellExecute «runas», без командной строки.
- Групповая политика Windows: `HKLM\SOFTWARE\Policies\RRCKI Mail` — `UpdateDisabled`
  (DWORD), `UpdateUrl` (строка) важнее файла `update.json`. Установщик (с правами
  администратора) создаёт `%ProgramData%\RRCKI Mail` с владельцем «Администраторы» и
  правом записи только для них.
- `latest.json` подписывается в CI ключом Ed25519 (секрет `UPDATE_SIGNING_KEY`),
  подпись — `latest.json.sig`, открытый ключ встроен в `updater.rs`
  (`UPDATE_PUBLIC_KEYS`, можно несколько — для смены ключа).
- Без верной подписи обновление не предлагается; без корректной SHA-256 файл
  не скачивается; версия не выше текущей не предлагается (нет отката).
- Только https; источник меняет только администратор (`update.json` в
  `/etc/rrcki-mail/` или `%ProgramData%\RRCKI Mail\`). Отладочные переменные
  `RRCKI_E2E_*` в релизной сборке не действуют.
- Для GPO рекомендуется отключить самообновление (`"disabled": true`) и раздавать
  проверенные пакеты из внутреннего хранилища.
- Подпись кода Windows (Authenticode) и deb/rpm не выполняется — нужен сертификат
  организации; пакеты проверяются по `SHA256SUMS.txt` + `SHA256SUMS.txt.sig`.

### Проверка релиза вручную
```sh
base64 -d SHA256SUMS.txt.sig > /tmp/sums.sig
echo "MCowBQYDK2VwAyEAUhcIkgOlNtHqJjtYlNf4Ij6HHuRbEgFNh+zptMcVBaY=" | base64 -d > /tmp/pub.der
openssl pkey -pubin -inform DER -in /tmp/pub.der -out /tmp/pub.pem
openssl pkeyutl -verify -pubin -inkey /tmp/pub.pem -rawin -in SHA256SUMS.txt -sigfile /tmp/sums.sig
sha256sum -c SHA256SUMS.txt --ignore-missing
```

## Политика администратора
Файл `policy.json` в `/etc/rrcki-mail/` (Linux) или `%ProgramData%\RRCKI Mail\`
(Windows); в Windows — также групповая политика `HKLM\SOFTWARE\Policies\RRCKI Mail`
(значения реестра важнее файла):

```json
{
  "remoteImages": "direct",
  "internalNetworks": ["10.0.0.0/8", "144.206.0.0/16"],
  "rememberPassword": true,
  "allowRememberPassword": true,
  "shareLinkDays": 30,
  "localStore": true,
  "offlineDays": 30
}
```
| Параметр | Реестр | Смысл |
|---|---|---|
| `remoteImages` | `RemoteImages` (строка) | `direct` / `proxy` / `off` — картинки из интернета в письмах |
| `internalNetworks` | `InternalNetworks` (строка через запятую) | сети, куда загрузчик картинок не обращается |
| `rememberPassword` | `RememberPassword` (DWORD) | галочка «Запомнить пароль» по умолчанию |
| `allowRememberPassword` | `AllowRememberPassword` (DWORD) | 0 — запоминать пароль нельзя |
| `shareLinkDays` | `ShareLinkDays` (DWORD) | срок публичных ссылок «Отправить ссылкой» (по умолчанию 30, 0 — без срока) |
| `localStore` | `LocalStore` (DWORD) | 0 — ничего из почты не хранить на компьютере (индекс и письма; уже сохранённое удаляется при входе) |
| `offlineDays` | `OfflineDays` (DWORD) | наибольший срок хранения писем на компьютере, дней (пользователь выбирает не больше; 0 — только индекс заголовков) |

Ссылка для письма берётся существующая только если у неё есть срок; ссылки без срока
для писем не используются.

## Сборка и поставка
- Задача публикации релиза работает в среде GitHub `release`: в настройках репозитория
  включите для неё обязательное подтверждение и держите `UPDATE_SIGNING_KEY` только там.
- GitHub Actions закреплены по SHA коммита; токен по умолчанию — только чтение,
  `contents: write` — лишь у задачи релиза.
- В CI: `npm audit --omit=dev --audit-level=high`, `cargo audit` (RustSec) для обеих
  сборок, clippy `-D warnings`, юнит-тесты.
- К релизу прикладываются SBOM (CycloneDX: Rust, Rust для Astra 1.7, frontend),
  `SHA256SUMS.txt` и подписи.
- Рекомендуется: защита ветки `main` (обязательные проверки, запрет force-push),
  2FA для всех, кто может пушить, отдельная среда (environment) с подтверждением для
  задачи релиза — тогда секрет подписи доступен только ей.

## Развёртывание в организации (рекомендации аудита)
1. **Терминальная ферма и общие Linux-хосты.** `/etc/rrcki-mail/update.json` →
   `{"disabled": true}`; пакеты ставит администратор из внутреннего репозитория.
   Проверьте Secret Service (gnome-keyring) в сеансах — без него пароль спрашивается
   при каждом запуске.
2. **Внутренний APT/RPM-репозиторий с подписью НИЦ** (закрывает H2 для Linux):
   скачать пакет релиза → проверить `SHA256SUMS.txt.sig` и сумму (см. выше) →
   добавить в репозиторий (`aptly`/`reprepro`, `createrepo_c`), подписанный GPG-ключом
   организации → на машинах обновление штатным `apt`/`dnf`.
3. **Windows / GPO.** MSI (`*_x64_ru-RU.msi`) ставится для всех пользователей
   (perMachine); WebView2 Runtime разверните заранее отдельным пакетом (установщик
   иначе скачивает его из интернета). Самообновление — `UpdateDisabled=1` в
   `HKLM\SOFTWARE\Policies\RRCKI Mail`, новые версии — через GPO/SCCM. Подпись
   Authenticode требует сертификата подписи кода организации (signtool в CI или на
   отдельной машине) — после этого возможны правила AppLocker/WDAC по издателю.
4. **Репозиторий и релизы (H1).** Settings → Environments → `release`: Required
   reviewers; `UPDATE_SIGNING_KEY` удалить из Repository secrets и добавить в секреты
   среды `release`. Settings → Branches: защита `main` (обязательные проверки, запрет
   force-push). 2FA для всех с правом записи; перенос репозитория в организацию НИЦ.
5. **Серверы.** DAV/SOGo — только https; IMAP с UIDPLUS и MOVE; в Nextcloud —
   обязательный срок публичных ссылок; в SOGo/Sieve — запрет переадресации на внешние
   домены, если этого требует политика ИБ.
6. **Astra 1.7 (M7).** Сборка на Tauri 1 и WebKitGTK 4.0 из Astra 1.7: безопасность
   показа писем зависит от обновлений WebKitGTK в 1.7, разделения команд по окнам там
   нет. Держите 1.7 обновлённой и планируйте перевод на 1.8.
